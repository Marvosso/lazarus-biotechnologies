# Professional Portfolio Architecture

**Status:** Accepted
**Date:** 2026-09-10

## Purpose

The professional portfolio will provide evidence of technical learning,
project implementation, security analysis, and professional development.

Lazarus Biotechnologies will serve as a flagship case study but the
portfolio architecture must support arbitrary future projects and
skills without structural redesign.

## Portfolio Principles

1. Evidence over claims.
2. Projects demonstrate applied skills.
3. Skills link to evidence.
4. Historical progression is preserved.
5. Failures and lessons learned may be showcased where valuable.
6. Sensitive project information is sanitized before publication.
7. The portfolio architecture must remain technology-independent.

## Primary Content Types

### Projects

Substantial implementations or products.

Examples:

- Lazarus Biotechnologies
- SentinelView
- AccessFlow

### Case Studies

Focused analyses of a specific technical or security problem.

Examples:

- IAM access review
- Vulnerability remediation
- Security incident investigation
- Detection engineering exercise

### Skills

Evidence-backed demonstrations of capabilities.

Examples:

- Identity & Access Management
- Power BI
- SQL
- Python
- Vulnerability Management
- Security Analytics

### Learning

Historical records demonstrating development of new capabilities.

## Evidence Types

Evidence may be:

- Visual
- Technical
- Analytical

Projects should use the strongest evidence appropriate to the work.

## Publishing Boundary

Internal project data must not automatically become public portfolio
content.

Information must pass through a review and sanitization process before
publication.

Public portfolio content must not expose:

- Credentials
- API keys
- Private keys
- Sensitive configuration
- Hidden scenario ground truth
- Real personal information
- Unsafe attack-range information
- Actual protected information

## Historical Snapshots

Major project milestones should create sanitized snapshots recording:

- Date
- Project phase
- Status
- Architecture version
- Technologies
- Skills demonstrated
- Major accomplishments
- Security metrics
- Known limitations
- Lessons learned

Snapshots should allow project progression to be reconstructed over time.

## Skill Evidence

Skills should not rely solely on self-assigned proficiency levels.

A skill should instead reference evidence demonstrating where and how
the capability was applied.

## Lazarus Relationship

Lazarus Biotechnologies is one project within the professional portfolio.

The public portfolio should clearly identify Lazarus as a fictional,
simulated enterprise cybersecurity environment and must never imply
that Lazarus Biotechnologies was an actual employer.
